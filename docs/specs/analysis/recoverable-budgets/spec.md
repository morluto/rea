# Recoverable analysis budgets

## Problem

Several analysis workflows discard selected facts at fixed retention boundaries.
Existing runtime settings control only some resources. Increasing a deadline,
heap, or header allowance cannot repair an independent count or representation
limit. Desktop readers also duplicate policy in generated Python.

Related discussions: [#6176](https://github.com/morluto/rea/issues/6176),
[#8434](https://github.com/morluto/rea/issues/8434),
[#5808](https://github.com/morluto/rea/issues/5808), and
[#8978](https://github.com/morluto/rea/issues/8978).

## Requirements

1. Preserve defaults unless representative completed-task measurements justify
   a calibration; preserve caller selections, Evidence identity, omission,
   unknown coverage, and cleanup authority. Changes must not grant new target
   execution, injection, mutation, installation, or network authority.
2. Keep source validity independent of retention completeness. In particular,
   an overlong but terminated kernel modinfo value is not malformed merely
   because REA omitted its text.
3. Preserve exact exhaustion causes and give a next action addressing that
   resource. GDB byte, record-count, and single-line limits must remain distinct.
4. Offer caller selection, continuation, or a bounded policy override for the
   reviewed desktop projections, Apktool string tables, JavaScript semantic
   precision, source maps, historical captures, provider capture retention,
   artifact/managed representations, and producer admission/output limits.
5. Interpret each policy at its owner. Parent and child process checks consume
   the same accepted values; generated Python consumes the desktop policy rather
   than maintaining independent numeric defaults. Reject invalid values rather
   than clamping or silently falling back.
6. Retain justified format, runtime, protocol, and ownership constraints.
   Distinguish them from adjustable resource policy and external client budgets.
   A larger delivery page cannot recover facts already discarded by a producer.
7. A runtime default update affects new accepted operations only. Explicit
   per-call choices win. Report effective value, units, applicable control and
   retry/restart scope without claiming active-worker telemetry.
8. Artifact recognition that cannot examine the selected carrier within its
   accepted resource policy remains limited/unknown, never examined absence.
   Preserve the exhausted cause through classification and retained probe facts.
   Add cohesive per-call Bun, .NET bundle, Node SEA and Godot admission controls
   at their producing owners, including preallocation and expansion checks.
9. Desktop task checks must admit the actual shipped seed representation under
   the same selected view policy as the generated reader. Acquisition/export
   budgets remain separate from runtime view admission.
10. Local source-location tracing offers opt-in compact retained delivery and
    bounded access to mapping alternatives and embedded text. Preserve complete
    Evidence, source identity, selected positions, unknowns and every equal-point
    mapping; compact output must not repeat the raw map or entire source text.
11. Desktop SQLite projections share a configurable per-table encoded-view
    allowance with generated readers and check it before retaining rows. Keep
    the independent native SQLite value/record and worker-reply envelopes
    explicit; a projected-view override does not raise those constraints.

## Acceptance

Exercise the exhausted boundary and its advertised repair through the strongest
practical public or production workflow. Use small lowered-budget fixtures when
they prove the same boundary without large allocations. Preserve independent
malformed-input, cancellation, identity, cleanup and fixed-protocol controls.
Record real-provider coverage separately from simulated process/protocol tests.

## Non-goals

Unbounded analysis, changing all numeric constants, treating format bit widths as
preferences, raising another application's client buffer/deadline, recovering
lost live observations retroactively, or adding new execution authority.
