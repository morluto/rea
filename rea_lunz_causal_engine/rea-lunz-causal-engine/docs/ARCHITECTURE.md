# Architecture

## Data flow

1. The MCP tool accepts a bounded query, package coordinates, and optional local facts tied to REA Evidence identifiers.
2. Query terms are sanitized before network dispatch. External discovery runs against allowlisted HTTPS sources: DuckDuckGo HTML search, npm registry, deps.dev v3, OSV.dev, and selected official technical domains.
3. Retrieval uses explicit request timeouts, manual redirect rejection, bounded response readers, and an in-memory TTL cache.
4. Retrieved records are normalized into source objects with URL, title, excerpt, excerpt SHA-256, retrieval timestamp, source type, entity identity, reliability, query-match score, freshness score, and derived quality score.
5. The deterministic graph builder creates typed nodes, evidence edges, contradiction candidates, package relationships, and explicitly provisional causal hypotheses.
6. The graph validator checks bounded graph shape, known relation vocabulary, valid endpoints, source hashes/identities, source allowlist, exact API entity identity, confidence bounds, provenance links, and contradictory relationships.
7. REA wraps the graph and its quality report in its established Evidence format and records it using the current session's Evidence writer.
8. The fidelity-report tool independently evaluates supplied REA observations and emits structured JSON plus Markdown.

## Trust boundaries

External HTML, source pages, package metadata, and advisory text are evidence data, never executable instructions. Web requests accept only HTTPS URLs with approved hosts. Network redirects are not followed, which avoids redirect-based allowlist escape. Query sanitation removes code fences and quoted source literals, and only normalized query terms are sent to external search. No raw source file is submitted.

The validation tool uses an in-process provenance ledger. A source object must both pass deterministic checks and match the exact canonical representation registered during retrieval. The full graph must also match the canonical snapshot captured at research time. This detects supplied or modified source records that were not generated by the current engine instance. Evidence graphs validated by a fresh engine instance must first be researched again in that instance.

## Scoring

Source quality combines source-type reliability, lexical query relevance, and a freshness floor. Per-source contributions are capped by independent registrable domain using noisy-OR aggregation. The implementation does not assume source independence for two hosts under the same recognized registrable domain. Edge confidence cannot exceed the best supporting source quality. API metadata requires explicit entity match. Causal relations remain candidates until local code-path evidence and behavior tests confirm them.

## REA integration points

The installer registers the feature through REA's canonical `TOOL_CONTRACTS`, `TOOL_EFFECTS`, and `createServer` composition. It uses the existing `toolRegistrationOptions`, `createEvidence`, and `server.delivery.toEvidenceToolResult` paths rather than creating a parallel MCP server or an alternate Evidence format. The copied runtime module is added to `dist` by the existing build scripts.
